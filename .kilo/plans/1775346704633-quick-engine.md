# SR-Player Layout Redesign - rmpc Style

## Goal
Reorganize the SR-Player TUI layout to match the rmpc aesthetic while keeping the album artwork on the right side and finding a place for the ASCII Apple logo.

## Current Layout
```
+---------------------------------------------------+
|  Search Bar (topView) - 3 rows                    |
+----------------+------------------+---------------+
| Left Panel     | Center Panel     | Right Panel   |
| (34 cols)      | (flexible)       | (36-38 cols)  |
| Playlists      | Track List       | Now Playing   |
| + Info Panel   | / Search Results | / Queue       |
+----------------+------------------+---------------+
|  Status Bar (2 rows)                              |
+---------------------------------------------------+
```

## New Layout (rmpc-inspired, cover on right)
```
+---------------------------------------------------+
|  ASCII Logo + Search Bar (top bar)               |
+------------------------+--------------------------+
| Left Panel (flexible)  | Right Panel (artwork)    |
|                        |                          |
| - Track List           | - Album Artwork          |
| - Search Results       | - Track Info             |
| - String List          | - Queue (tab toggle)     |
|                        |                          |
+------------------------+--------------------------+
|  Visualizer Bars                                  |
+---------------------------------------------------+
|  Status Bar (progress + controls + hints)         |
+---------------------------------------------------+
```

## Files to Modify

### 1. `internal/ui/layout.go`
**Changes:**
- Remove the 3-column layout, switch to 2-column (left content + right artwork/info)
- New `PanelSizes()` returns: `leftW, rightW, mainH, visualizerH`
- `leftW` = flexible (takes remaining width after right panel)
- `rightW` = fixed ~40 cols for artwork display
- `visualizerH` = ~4-6 rows at bottom of main area
- Update `Render()` to compose: topBar -> mainRow(leftPanel + rightPanel) -> visualizer -> statusBar
- Keep tab bar for Now Playing / Queue toggle on right panel
- Remove the old 3-column horizontal join

### 2. `internal/ui/panels/tracklist.go`
**Changes:**
- Add "Album" column to the track list delegate
- New column widths: Title (flexible), Artist (~25), Album (~25), Duration (5)
- Update header to show: "Title  Artist  Album  Duration"
- Update `Render()` method in `trackDelegate` to render 4 columns
- Ensure truncation works for all 4 columns

### 3. `internal/ui/panels/nowplaying.go`
**Changes:**
- Remove the visualizer from this panel (moved to bottom area)
- Adjust height calculations since visualizer is no longer here
- Keep: artwork rendering, track title/artist/album, state icon, key hints
- The panel becomes simpler: just artwork + track info

### 4. `internal/ui/statusbar.go`
**Changes:**
- Keep the progress bar and controls as-is
- The visualizer is now a separate component rendered above the status bar

### 5. `internal/ui/app.go`
**Changes:**
- Update `View()` method to use new layout composition
- Add visualizer rendering as a separate bottom section
- Adjust panel sizing calls to match new layout dimensions
- Update `Update()` for `tea.WindowSizeMsg` to use new panel sizes
- Add ASCII Apple logo rendering in the top bar area
- Keep all existing functionality (focus navigation, key bindings, etc.)

### 6. New: `internal/ui/visualizer.go` (or integrate into existing)
**Changes:**
- Extract `renderVisualizer` from `nowplaying.go` into its own file or keep as shared function
- Create a `VisualizerBar` component that renders at the bottom of the main area
- Width spans the full main area width
- Height is ~4-6 rows
- Uses the same BPM-synced animation logic

### 7. ASCII Apple Logo Integration
**Changes:**
- Load `assets/am.txt` at startup or embed it
- Render the ASCII logo in the top bar area alongside the search input
- The logo takes the left portion of the top bar, search input takes the right
- Or render logo as a small banner above the main content area
- Alternative: Show logo only on initial load, then replace with search bar

## Detailed Implementation Steps

### Step 1: Update layout.go
- Change `PanelSizes()` to return `(leftW, rightW, mainH, visH int)`
- `rightW` = 40 (for artwork), clamped to width/3 min 36
- `leftW` = width - rightW, min 40
- `visH` = 5 (visualizer height)
- `mainH` = height - topH - statusH - visH
- Update `Render()` signature to accept visualizer string
- Compose: `topBar -> mainRow -> visualizer -> statusBar`

### Step 2: Update tracklist.go
- Modify `trackDelegate.Render()` to add Album column
- Column split: titleW = totalW - artistW - albumW - durW - spacing
- artistW = ~25, albumW = ~25, durW = 5
- Update header in `View()` to include "Album" column
- Update `formatTrackDuration` stays the same

### Step 3: Update nowplaying.go
- Remove visualizer rendering from `View()`
- Remove `visHeight` calculation
- Content becomes: artwork -> title -> artist -> album -> state -> keys
- Adjust `SetSize()` and height calculations accordingly

### Step 4: Create visualizer component
- Move `renderVisualizer` function to be accessible from app level
- Create visualizer bar that spans full width below main content
- Same BPM-synced animation, just wider

### Step 5: Update app.go
- Update `View()` to compose new layout
- Add ASCII logo rendering in top area
- Update panel size calculations in `Update()` for `WindowSizeMsg`
- Keep all existing message handling and key bindings

### Step 6: ASCII Logo
- Read `assets/am.txt` at startup
- Render in top bar: left side = logo, right side = search input
- Or integrate as a small header above the main content
- Consider truncating or scaling the logo for smaller terminals

## Key Bindings (unchanged)
- All existing key bindings remain the same
- Tab navigation, focus switching, playback controls all preserved
- The visual change is purely layout reorganization

## Color Scheme (unchanged)
- Keep the existing dark theme with red accent (#FA243C)
- All panel styles, borders, and selections remain the same
